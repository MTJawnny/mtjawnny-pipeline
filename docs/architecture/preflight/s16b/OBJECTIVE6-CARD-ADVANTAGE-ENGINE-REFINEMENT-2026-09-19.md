## 2. Current placement

### Card Advantage

`Card Advantage` is preserved as established Magic/community theory vocabulary and downstream strategic/educational language.

Foundry's narrower canonical accounting is expressed through underlying typed resource facts and a derived **Card Resource Differential** projection (final name still subject to naming audit).

### Engine

`Engine` is no longer a canonical hard parent family.

The mechanical work survives as processor coordinates/signatures such as:

- input/event kind;
- aggregation;
- firing multiplicity/cap;
- opportunity window;
- output type/magnitude;
- processor retention;
- external fuel;
- stored capacity;
- feedback dependency.

`Engine`, `Card Engine`, `Mana Engine`, and related phrases remain useful derived/search/community labels over those facts.

### Stored Capacity

The stored-capacity pattern remains a coordinate/mechanical pattern, not a trunk.

### Setup vs operating dependency

The distinction remains canonical as hard dependency facts:

- setup requirement;
- continuing operating requirement;
- effect of current use on future eligibility.

## 3. Retained-resource correction

The old shorthand that a permanent left behind can be credited as an additional card resource is now tightened.

The permanent is the same underlying card-origin object that moved from a prior zone; persistence alone does not create another card.

Derived resource accounting compares distinct underlying card-origin resources and access before/after without double-counting the source. Independent functionality remains strategically relevant but is not permission to count the same card object twice.
